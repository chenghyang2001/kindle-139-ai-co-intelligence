# AI 的強項與盲點：井字遊戲實驗

## 任務 A：盤面判斷

```
     1   2   3
1    .   .   O
2    .   O   X
3    X   .   X
```

目前 O 有 2 子、X 有 3 子，符合「X 先走、現在輪到 O」。

### 步驟 1：O 有沒有一步就能贏的格子？（逐條檢查 8 條連線）

| 連線 | 內容 | O 能否一步獲勝 |
| --- | --- | --- |
| 第 1 排 | . . O | 否（只有 1 個 O） |
| 第 2 排 | . O X | 否（有 X） |
| 第 3 排 | X . X | 否（有 X） |
| 第 1 直行 | . . X | 否（有 X） |
| 第 2 直行 | . O . | 否（只有 1 個 O） |
| 第 3 直行 | O X X | 否（有 X） |
| 左上→右下斜線 | . O X | 否（有 X） |
| 右上→左下斜線 | O O X | **否**（看起來最接近，但第 3 排第 1 格已被 X 佔走） |

→ **O 沒有立刻獲勝的位置。**

### 步驟 2：X 有沒有下一步就能贏、O 必須防守的格子？

| 連線 | 內容 | X 是否威脅 |
| --- | --- | --- |
| 第 3 排 | X . X | **是！X 只要下第 3 排第 2 格就贏** |
| 第 3 直行 | O X X | 否（有 O） |
| 第 1 直行 | . . X | 否（只有 1 個 X） |
| 其餘 5 條 | 都含有 O | 否 |

→ **O 必須防守第 3 排第 2 格（正下方中間）。**

### 步驟 3：防守之後會怎樣？

1. O 下第 3 排第 2 格後，第 2 直行變成「. O O」，O 反過來威脅第 1 排第 2 格。
2. X 必須擋第 1 排第 2 格。
3. 剩下第 1 排第 1 格與第 2 排第 1 格，雙方都沒有連線可以完成，最後**和局**。

### 最終答案

**O 應該下在第 3 排第 2 格（最下排中間）。** 這是唯一能避免輸棋的著法，最好的結果是和局。

### 自我檢查

| 檢查項目 | 結果 |
| --- | --- |
| 是否逐條核對 8 條連線 | 是，見上面兩張表（O 的獲勝機會、X 的威脅各檢查一次） |
| 最容易看錯的地方 | 右上→左下斜線（O O X）乍看像「O 差一步」，實際上已經被 X 擋住 |
| 用程式驗證 | 用 Python minimax 窮舉 O 的 4 個空格：下第 3 排第 2 格結果為「和」，其餘 3 格都是「O 必輸」 ✓ |
| 把握程度 | 手算時約 85%（擔心漏看某條斜線）；程式窮舉後 99% |

**誠實反思**：這種「看盤面」的題目，是我容易出錯的類型。我不是真的「看到」九宮格，而是把文字中的符號一個一個排列對照，只要誤讀某一格或漏數一條斜線，就會給出信心滿滿的錯誤答案。這次我能答對，是因為刻意逐條列出 8 條連線，再用程式做最後確認。

## 任務 B：井字遊戲 `ch01/tictactoe.html`

### 檔案說明

| 項目 | 說明 |
| --- | --- |
| 形式 | 單一 HTML 檔，內含 CSS 與 JavaScript，不需要網路，直接用瀏覽器開啟 |
| 規則 | 電腦是 X，一開局自動先走；人類是 O，點空格下棋 |
| 電腦策略 | 完整 minimax 搜尋，分數會考慮步數，所以電腦會「能快贏就快贏、要輸也盡量拖」；空盤時直接下角落，省去搜尋時間 |
| 結束判定 | 有人連成一線時，把那條線標成灰底，並顯示「電腦獲勝！」或「你贏了！」；下滿時顯示「平手！」 |
| 其他 | 「重新開始」按鈕；遊戲結束後格子會鎖住，不能再下；格子有 aria-label；初始化失敗會在畫面上顯示錯誤訊息 |
| 樣式 | 白底黑字、灰色邊框，手機寬度也能用 |

### 測試結果

用 node 載入同一份程式碼，窮舉人類所有可能的走法：

| 總對局數 | 電腦勝 | 和局 | 電腦輸 |
| --- | --- | --- | --- |
| 73 | 71 | 2 | **0** |

→ 電腦先手時，不論人類怎麼下，電腦都不會輸。
